## 知识点选择与衔接逻辑

| 知识点 | 与已有知识的衔接 |
| --- | --- |
| if 基本形状（冒号 + 4 空格缩进） | 强调缩进是语法本身，用「有缩进 vs 无缩进」两行对照说明谁受条件控制 |
| `=` 赋值 vs `==` 判断 | 用户早期有混淆风险，专门列表格对比；指出 `if score = 87:` 报 SyntaxError（好事），`if score:` 不报错但语义变了（危险） |
| else / elif 多分支 | 核心规则「从上往下命中第一个就停」→ 推出「elif 顺序必须从严格到宽松」；顺序错则**不报错但逻辑全错** |
| and / or / not | 提到短路行为，为后续「先查密钥再发请求」预留认知 |
| 真值（truthiness） | 直接复用回顾里的 `len([])` = 0；列出空列表/空字符串/0/None 为假；同时提醒 `if score:` 在 score=0 时的坑 |
