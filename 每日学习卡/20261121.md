## 今日知识点（25 分钟）

### 1. Git 是什么？GitHub 又是什么？（5 分钟）

一句话区分，别混：

| | 是什么 | 装在哪 | 类比 |
| --- | --- | --- | --- |
| **Git** | 一个"版本管理工具"（软件/命令） | **装在你电脑上**（需自行安装，见下一节） | 一台能拍快照的相机 |
| **GitHub** | 一个"存放代码快照的网站" | 在**云端网站**上（github.com） | 一个展示快照的画廊 |

Git 帮你做的最核心一件事：**给代码的某个状态拍一张快照（叫"提交"），永久保存**。以后你改代码改崩了，一句话就能回到上次那个能跑的版本。GitHub 则把这些快照存到网上，附带一个漂亮的网页，别人能看到你的代码和提交历史。

为什么求职必须用它：**GitHub 提交记录就是程序员的"作品痕迹"**。面试官点开你的主页，能看到你从第一行代码开始的持续记录——这比简历上写"熟悉 Git"有说服力得多。总览里从 M1 就要求你开始攒，今天就是第一天。

### 2. 先安装 Git（5 分钟）

**你的电脑上目前没有装 Git**——需要自己装一次，只装这一次，以后都能用。

1. 打开官网 `git-scm.com`，下载 Windows 版安装包（64 位）；
2. 双击安装，**除了"选择默认编辑器"那一步建议选 Visual Studio Code（如果你装了），其余一路点 Next 用默认值**即可；
3. 装完后，**重新打开一个新的终端窗口**（关掉旧的再开，让 PATH 生效），输入：

```bash

```

看到类似 `git version 2.xx.x.windows.x` 就装好了。版本号不用和这里一致，最新的就行。

> 说明：我这边用的工具内部自带一份便携版 Git，那是为了工具自己工作用的，**不会装到你的系统上**。所以你在自己的终端里敲 `git` 找不到命令是正常的——必须按上面装一次。

> 这一步看着简单，却是从"看代码"到"有自己的代码"的关键一跳。**代码存成文件，才真正属于你。**

### 4. 配置身份 + 建仓库（5 分钟）

**配置身份**——Git 每次提交都要记"谁提交的"，只配一次，以后不用再配。在终端运行（把名字和邮箱换成你自己的）：

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@example.com"
```

**建仓库**——进入你的项目目录，告诉 Git"从这里开始，这个文件夹归我管"：

```bash
cd E:/ai_create/学习计划
git init
```

我实跑确认过 `git init` 的输出，会显示 `Initialized empty Git repository in ...`。你可能会看到一段关于 `master` / `main` 分支名的英文提示（hint）——**那不是报错**，只是 Git 在提醒你默认分支以后会改名，忽略即可。想消掉它，可以顺手跑一句 `git config --global init.defaultBranch main`。

### 5. 提交三连：status → add → commit（8 分钟）

这是今天最核心的动作，记住三步节奏——**看状态 → 暂存 → 提交**。

> ### 🔧 命令卡片：`git status` / `git add` / `git commit`
>
> **`git status`——看当前状态**
> - 它是什么：告诉你"哪些文件变了、哪些还没被跟踪"。
> - 参数：无（今天只用光秃秃的 `git status`）。
> - 返回/输出：一段文字。首次会看到 `Untracked files:` 下面列着你的 `练习/` 和 `每日学习卡/` 等文件夹——意思是"这些文件 Git 看到了，但还没纳入管理"。
> - 最小例子：`git status`
> - 常见坑：看到满屏红色不用慌，红色就是"新文件还没跟踪"，下一步 add 就对了。**提交前后都该跑一下 status，确认没有漏掉文件**。
>
> **`git add`——暂存（把文件放进"待提交清单"）**
> - 它是什么：告诉 Git"这个文件我要拍进快照"，放进去叫"暂存区"。
> - 参数：`git add 文件名` 或 `git add .`（`.` 表示当前目录所有变化，今天用这个最省事）。
> - 返回/输出：**成功时没有任何输出**——这是新手最容易懵的地方，没消息就是好消息。
> - 最小例子：`git add .`
> - 常见坑：你可能会看到一行 `warning: LF will be replaced by CRLF`——这是 Windows 换行符的正常提示，**不是报错**，忽略即可。
>
> **`git commit`——提交（正式拍快照）**
> - 它是什么：把暂存区的文件永久存成一个版本。
> - 参数：`git commit -m "提交说明"`。`-m` 后面跟一句话，说明这次改了什么——**必写**，这是给未来的自己和别人看的。
> - 返回/输出：一段确认信息，如 `[master (root-commit) 4ab0c53] 首个提交` + `1 file changed`。
> - 最小例子：`git commit -m "首个提交：命令行待办清单"`
> - 常见坑：① 没先 `git add` 就 commit，什么都不会提交；② 没配 user.name/email 会报错（上面第 3 步配过了）；③ **提交说明别写"更新"这种没信息量的话**，写清"做了什么"。

**完整走一遍**（我实跑验证过每一步的输出）：

```bash
cd E:/ai_create/学习计划
git status                              # 看到一堆 Untracked files
git add .                               # 暂存所有文件（无输出=成功）
git commit -m "首个提交：命令行待办清单"   # 拍下第一张快照
git log --oneline                       # 查看提交历史，能看到刚才那条
```

`git log --oneline` 会显示类似 `4ab0c53 首个提交：命令行待办清单`——前面那串是快照编号，后面是你的说明。**看到这一行，你就完成了第一次提交。**

### 6. 推上 GitHub（4 分钟）

本地提交完成了，但还在你电脑上。要放到网上，需要：

**① 注册 / 登录 GitHub**（github.com），点右上角 `+` → `New repository` 建一个新仓库，名字随便起（如 `todo-cli`），**不要勾选** README / .gitignore / license（保持空仓库，否则会有冲突）。

**② 关联远程仓库并推送**——在 GitHub 建好后会显示一串地址，复制它（形如 `https://github.com/你的用户名/todo-cli.git`），然后在终端运行：

```bash
git remote add origin https://github.com/你的用户名/todo-cli.git
git branch -M main
git push -u origin main
```

> ### 🔧 命令卡片：`git remote add` / `git push`
>
> **`git remote add origin <地址>`**
> - 它是什么：给远程仓库起个别名叫 `origin`（习惯叫法），记下"要推到哪"。
> - 参数：别名 + 仓库地址。
> - 返回/输出：成功无输出。
> - 坑：地址写错、或重复 add 同一个别名会报错（重复了就用 `git remote set-url origin <地址>` 改）。
>
> **`git push -u origin main`**
> - 它是什么：把本地的提交推到远程仓库。
> - 参数：`-u` 是记住这次的关联，以后直接 `git push` 就行；`origin` 是上面起的别名；`main` 是分支名。
> - 返回/输出：一段上传进度，最后显示成功。
> - 坑：**GitHub 现在不接受账号密码，要用 Personal Access Token（个人访问令牌）**——在 GitHub → Settings → Developer settings → Personal access tokens 生成，推送时当密码粘贴。第一次会弹窗要你登录，按提示操作即可。

推完后刷新 GitHub 仓库页面——你的代码和提交记录就在上面了。截图存好，这就是你求职作品集的第一块砖。
