## 今日知识点（27 分钟）

### 1. 模块：一个 .py 文件就是一个模块（8 分钟）

**模块（module）是什么**：一个 `.py` 文件。你把函数写进 `tasks.py`，这个文件就是一个叫 `tasks` 的模块；别的文件用 `import tasks` 就能用它里面的函数。像把工具分装到不同的工具箱，用哪个搬哪个。

**怎么用**——两种写法，我都在临时目录实跑验证过：

```python
import tasks                    # ① 把整个模块拿进来
tasks.add(todo, "装 Python")    # 用的时候要加模块名前缀

from tasks import add           # ② 只把某个函数拿进来
add(todo, "装 Python")          # 用的时候直接写函数名
```

实跑输出（我验证过第一种）：`type(tasks)` 是 `module`，`dir(tasks)` 能看到里面定义的 `add`、`show`。**结论：import 拿进来的是一个模块对象，函数挂在它下面。**

> ### 🔧 命令/语句卡片：`import`
>
> **① 它是什么**：Python 语句，用来"把别的模块里的代码加载进来用"。
>
> **② 两种语法**：
> - `import 模块名`：导入整个模块，用里面东西要写 `模块名.函数名`。
> - `from 模块名 import 函数名`：只导入指定的函数，用的时候直接写函数名。
>
> **③ import 时到底发生了什么（重点）**：Python 为了拿到那个文件里的函数，会把那个文件**从头到尾执行一遍**。所以文件里"没缩进在函数里"的代码（叫顶层代码，比如顶层的 `print`、顶层的 `while True`）会在 import 的瞬间就跑起来——你明明只想借个函数，它却顺便把别的事也干了。这种"顺手干了你没想让它干的事"，专业点叫**副作用**，大白话就是 **import 会连累顶层代码一起执行**。
>
> **④ `__name__` 是什么（这行的全部秘密）**：Python 自动给每个 `.py` 文件设的一个变量，你没写它但它一直存在。它的值取决于你怎么启动这个文件：
>
> | 你怎么启动这个文件 | 它的 `__name__` 等于 |
> | --- | --- |
> | 直接运行 `python demo.py` | `"__main__"`（字符串） |
> | 被别人 `import demo` | `"demo"`（就是文件名） |
>
> 所以 `if __name__ == "__main__":` 翻译成人话就是"**如果我是被直接运行的**"。把它下面的缩进代码圈起来，就实现了"直接运行才执行、被 import 就跳过"——这就是个门禁。
>
> **⑤ 实跑对比**（我跑出来的真实输出，一个字没改）：
>
> 有个 `demo.py`，内容是：
> ```python
> print("顶层：我被加载了")
>
> def hello():
>     print("hello 被调用")
>
> print("此时 __name__ 是：", __name__)
>
> if __name__ == "__main__":
>     print("我在 if 里，说明是直接运行")
> else:
>     print("我在 else 里，说明是被 import")
> ```
>
> 直接跑 `python demo.py` →
> ```
> 顶层：我被加载了
> 此时 __name__ 是： __main__
> 我在 if 里，说明是直接运行
> ```
>
> 另一个文件里写 `import demo` 再运行 →
> ```
> 顶层：我被加载了
> 此时 __name__ 是： demo
> 我在 else 里，说明是被 import
> ```
>
> 两次的 `__name__` 值不一样，`if` 就走了不同分支。就这么简单。
>
> **⑥ 常见坑 / 为什么必须用**：
> - ① 模块名就是文件名（不含 `.py`）——`tasks.py` 对应 `import tasks`，别写错。
> - ② 模块要和主程序在**同一目录**才找得到（今天都用同目录）。
> - ③ **拆分时一定要把 `while True` 主循环放进 `if __name__ == "__main__":`**。否则别人一 import 你的 `main.py`，菜单立刻启动、程序卡死在那儿。放进 if 里就两全：直接运行照样出菜单，被 import 时安静跳过、不添乱。

### 2. 包：装模块的文件夹（5 分钟）

模块多了要分类，就放进文件夹——**带 `__init__.py` 的文件夹就是"包"（package）**。像工具箱太多，再按"电工/木工"分柜子。

```
mypkg/                 ← 文件夹（包）
├── __init__.py        ← 必须有，告诉 Python"这是个包"（里面可以是空的）
└── utils.py           ← 包里的模块
```

用点号路径导入：

```python
from mypkg.utils import greet
print(greet("小明"))   # 你好，小明
```

我实跑验证过，输出是 `你好，小明`。`__init__.py` 可以什么都不写，但**少了它 Python 可能认不出这是包**（Python 3.3+ 有命名空间包的例外，但今天一律带上，养成习惯）。

三类模块要分清：

| 类别 | 例子 | 哪来的 |
| --- | --- | --- |
| 标准库 | `os`、`sys`、`random` | Python 自带，装好就有 |
| 第三方库 | `requests`、`pytest` | 用 pip 装（下一节） |
| 自己的模块 | `tasks`、`mypkg.utils` | 你自己写的 .py 文件 |

### 3. pip：安装第三方库（7 分钟）

Python 强大的原因是全世界的人都在给它写库——这些库放在 **PyPI**（Python Package Index）这个大仓库里，`pip` 就是去那里拿货的"快递员"。

> ### 🔧 命令卡片：`pip install`
>
> **① 它是什么**：Python 的包管理工具，用来从 PyPI 下载并安装第三方库。
>
> **② 语法与常用参数**：
> - `pip install 库名`：装最新版。
> - `pip install 库名==2.31.0`：装指定版本（项目要稳定时用）。
> - `pip list`：看当前环境装了哪些库。
> - `pip uninstall 库名`：卸载。
>
> **③ 返回值 / 输出**：在终端打印下载和安装进度，成功时显示 `Successfully installed ...`。它不是 Python 里的函数，没有"返回值"，看终端输出判断是否成功。
>
> **④ 最小例子**：
> ```bash
> pip install requests
> pip list
> ```
>
> **⑤ 常见坑**：
> - ① **装到了哪个 Python 里**：电脑可能有多个 Python，`pip` 可能和 `python` 不是一套。用 `python -m pip install requests` 最稳——保证装到当前 Python 里。
> - ② 公司/校园网络可能要配镜像源，今天用不到，先知道有这回事。
> - ③ 别在系统全局装一堆库——下一节讲用虚拟环境隔离。

**requirements.txt**：项目用了哪些库、什么版本，写进这个文件，别人一句 `pip install -r requirements.txt` 就能装齐。这是项目交付的标准配置，今天先认识，等你装了第一个第三方库（M4 的 `requests`）再实操。

### 4. venv：给项目隔离环境（7 分钟）

**为什么需要**：你做项目 A 用了 `requests 2.30`，项目 B 需要 `requests 2.31`——装在同一个 Python 里会打架。`venv` 给每个项目造一个"独立房间"，各装各的库，互不干扰。

> ### 🔧 命令卡片：`python -m venv`
>
> **① 它是什么**：Python 标准库里的 `venv` 模块，用来创建一个隔离的虚拟环境（一个独立的 Python 副本 + 独立的库目录）。
>
> **② 语法**：`python -m venv 环境名`。环境名习惯叫 `venv` 或 `.venv`。
>
> **③ 返回值 / 输出**：成功时终端没输出，但会生成一个文件夹，里面有独立的 Python 和 pip。Windows 下 Python 在 `venv/Scripts/python.exe`（我实跑确认过这个路径）。
>
> **④ 最小例子**（Windows PowerShell）：
> ```powershell
> python -m venv venv          # 创建（只需一次）
> .\venv\Scripts\Activate.ps1  # 激活
> python --version             # 激活后确认用的是虚拟环境的 Python
> pip install requests         # 以后装的库都进这个环境
> deactivate                   # 退出
> ```
>
> 激活后命令行前面会出现 `(venv)` 字样——看到它就说明当前在虚拟环境里。
>
> **⑤ 常见坑**：
> - ① **PowerShell 激活可能报"禁止运行脚本"**：这是 Windows 的执行策略限制，执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 一次即可（或改用 Git Bash 激活：`source venv/Scripts/activate`）。
> - ② 激活后要确认 `python` 和 `pip` 指向虚拟环境（看 `(venv)` 前缀最直观）。
> - ③ `venv` 文件夹一般**不提交到 Git**（很大、且各机器不同）——M2 讲 .gitignore 时处理。

## 动手练习（20 分钟）

产出：`练习/20261122/` 下的多模块版本

把你的 `todo_cli_file.py` 拆成四个文件（结构如下，功能不变）：

```
练习/20261122/
├── tasks.py      ← 数据存取：load_tasks() / save_tasks()
├── ui.py         ← 界面：show_tasks() / 打印菜单
├── logic.py      ← 业务：add_task() / check_task()
└── main.py       ← 主控：import 上面三个 + while True 主循环
```

**拆分要点**（照着做就不会乱）：

1. 每个功能文件只放对应的函数，顶部写 `FILE = "tasks.txt"` 的放 `tasks.py`；
2. `main.py` 里这样导入：
   ```python
   import tasks
   import ui
   import logic

   todo = tasks.load_tasks()
   # 主循环里：ui.show_tasks(todo)、logic.add_task(todo, new)...
   ```
3. **把主循环放进 `if __name__ == "__main__":`**（今天的重点）——这样别的模块 import 它时不会误启动菜单：
   ```python
   if __name__ == "__main__":
       main()
   ```
4. 终端跑 `python main.py`，确认功能和昨天一模一样（菜单能出现、添加能保存）；
5. 顺手建一个虚拟环境跑一遍：`python -m venv venv` → 激活 → `python main.py` → `deactivate`。

**再提交一次**（可选但推荐）：回到 `E:/ai_create/学习计划`，`git add .` → `git commit -m "拆分为多模块结构"`，GitHub 提交记录就 +1 了。

> 求职相关：面试常问"你怎么组织一个项目的代码""为什么要拆模块"。你现在能拿自己的待办清单回答：按职责拆成数据/界面/业务/主控四个模块，主循环用 `if __name__ == "__main__"` 保护——这不是背的定义，是你自己拆过的项目。
