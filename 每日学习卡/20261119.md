## 今日知识点（25 分钟）

### 1. 定义一个函数：`def`（8 分钟）

> ### 🔧 函数卡片：`def`（定义函数）
>
> **① 它是什么**：Python 关键字，用来"打包一段代码并给它起名字"。打包后，喊这个名字就等于执行整段代码。像给一个菜谱贴标签，以后说"做那个菜"就行，不用每次重念步骤。
>
> **② 语法**（三个部分）：
>
> ```
> def 函数名(参数1, 参数2, ...):
>     缩进的函数体（要执行的代码）
> ```
>
> - `def`：必写，是 define（定义）的缩写
> - **函数名**：必写，自己起，规则同变量名（字母/数字/下划线、不能数字开头）；习惯用小写 + 下划线，如 `check_task`
> - **括号 `()`**：必写，哪怕没有参数也要写一对空括号
> - **冒号 `:`**：必写，漏了报 SyntaxError（和 if/for/while 一样）
> - **函数体**：缩进 4 格，属于这个函数
>
> **③ "定义"这个动作返回什么**：`def` 不返回业务数据——它把函数**注册**成一个可调用的对象，名字指向它。执行 `def` 那几行时，函数体**不会运行**，只有你"调用"时才运行（这是新手最需要分清的一点）。
>
> **④ 最小例子**：
> ```python
> def greet(name):
>     print(f"你好，{name}")
>
> greet("小明")   # 你好，小明
> greet("小红")   # 你好，小红
> ```
> 定义时不打印任何东西；调用两次才打印两行。
>
> **⑤ 常见坑**：① 只 `def` 不调用 → 什么都不发生（不是没写对，是你没喊它）；② 函数体忘了缩进 → IndentationError；③ 函数名和变量同名 → 后者覆盖前者，别混用。

**关键理解**：`def` 是**定义**（做菜谱），`greet("小明")` 是**调用**（按菜谱做菜）。定义一次，调用无数次。

### 2. 参数：让函数每次干不同的活（6 分钟）

`name` 就是参数——它是函数体里的**占位符**，调用时才填真实值。

**默认参数**：调用时不给就用默认值：

```python
def greet(name, greeting="你好"):
    print(f"{greeting}，{name}")

greet("小明")           # 你好，小明（用默认值）
greet("小红", "早上好")  # 早上好，小红（覆盖默认值）
```

规则：**带默认值的参数必须放在没有默认值的后面**（`def f(a=1, b)` 会报错）。因为调用时是按位置对应的，前面的有了默认值、后面没有就对不上。

**参数个数必须对上**：

```python
def add(a, b):
    return a + b

add(3, 5)     # 8
add(3)        # TypeError: 少一个参数
add(3, 5, 7)  # TypeError: 多了一个参数
```

### 3. 返回值：`return`（7 分钟）

> ### 🔧 函数卡片：`return`
>
> **① 它是什么**：函数里的"交作业"语句——把计算好的结果**送回给调用者**，同时**立刻结束函数**（后面的代码不执行）。
>
> **② 参数**：`return` 后面跟**一个表达式**（可以是变量、运算、字符串、列表，任何东西）。也可以只写 `return` 不带值。
>
> **③ 返回值**：就是把 `return` 后面的那个值交出去。调用方可以用变量接住：
>
> ```python
> result = add(3, 5)   # result 拿到 8
> ```
>
> **特殊但必记**：**函数里没有 `return`（或只写 `return` 不带值）时，返回 `None`**。`None` 是 Python 表示"什么都没有"的值。这点最容易忘。
>
> **④ 最小例子**：
> ```python
> def add(a, b):
>     return a + b
>
> print(add(3, 5))   # 8
>
> def say_hi():
>     print("hi")
>
> r = say_hi()       # 先打印 hi
> print(r)           # None —— 没有 return，返回 None
> ```
>
> **⑤ 常见坑**：① `print(x)` 和 `return x` 不是一回事——print 只是显示在屏幕上，函数照常返回 None；return 才是把值交出去。这是新手第一大坑。② `return` 之后的代码不执行（`return` 后面写 print 是死代码）。③ 想返回多个值，写成 `return a, b`，接到的是**元组**（今天不用深究，知道能这么写就行）。

**print vs return 的判断法**：问自己"**这个函数的结果，后面还要用吗**"？要拿去算、去判断、去存 → 用 `return`；只是给人看一眼 → `print` 就够。

### 4. 把逻辑抽成函数：实战（4 分钟）

看这段"检查某项在不在清单里"的代码：

```python
todo = ["装 Python", "学 if", "学 for"]
target = "学 for"

if target in todo:
    print(f"「{target}」在清单里")
else:
    print(f"「{target}」不在清单里")
```

想对不同清单、不同目标反复用，就把它抽成函数——**清单和目标变成参数，结果用 return 交出去**：

```python
def check_task(tasks, target):
    if target in tasks:
        return f"「{target}」在清单里"
    else:
        return f"「{target}」不在清单里"

print(check_task(todo, "学 for"))   # 「学 for」在清单里
print(check_task(todo, "学函数"))   # 「学函数」不在清单里
```

**注意这里的选择**：函数体里我用了 `return` 而不是 `print`——因为"检查结果"这个**值**，调用方可能想拿去做别的（比如决定下一步走哪个分支），而不只是看一眼。这就是上一条讲的区别落到实处。

> 求职相关：面试常问「函数和方法有什么区别」「return 和 print 有什么区别」。你今天亲手做的这个重构，就是最好的回答素材——不说定义，直接讲你把待办清单的哪段抽成了函数、为什么用 return。

## 动手练习（15 分钟）

产出：`练习/20261119/todo_cli_func.py`

把你 11-18 写的 `todo_cli_for.py` 重构成**带 3 个自定义函数**的版本：

```python
todo = ["装 Python", "学变量", "学 if"]


def show_tasks(tasks):
    """显示所有任务，带编号"""
    i = 1
    for t in tasks:
        print(f"{i}. {t}")
        i = i + 1


def add_task(tasks, new):
    """添加任务"""
    tasks.append(new)
    return f"已添加「{new}」"


def check_task(tasks, target):
    """检查某项是否在清单里"""
    if target in tasks:
        return f"「{target}」在清单里"
    else:
        return f"「{target}」不在清单里"


while True:
    print("\n===== 待办清单 =====")
    print("1. 查看清单")
    print("2. 添加任务")
    print("3. 检查某项")
    print("4. 退出")

    choice = input("请选择 1-4：")

    if choice == "1":
        show_tasks(todo)
    elif choice == "2":
        new = input("输入新任务：")
        print(add_task(todo, new))
    elif choice == "3":
        target = input("要检查哪项：")
        print(check_task(todo, target))
    elif choice == "4":
        print("再见！")
        break
    else:
        print("输入有误，请输入 1-4")
```

**跑起来验证三件事**：

1. 选 1 / 2 / 3 各操作一次——输出和昨天**完全一样**（功能没变）。
2. 看主循环（`while True` 下面那部分）——原来十几行的分支逻辑，现在**每个分支只剩一行**。这就是函数带来的"主流程清爽"。
3. 故意把 `check_task` 里的 `return` 改成 `print`，再看选 3 的输出——会先打印结果、再打印 `None`。亲眼对比一次，你就永远不会混 print 和 return。

> 那三行 `"""显示所有任务，带编号"""` 叫**文档字符串**（docstring），写在函数第一行、用三个引号包起来，是给看代码的人（包括未来的你）说明这个函数干嘛的。不写也能跑，但写了以后一看就懂——这是好习惯，今天顺手养成。

> 求职相关：这份代码现在有"数据（todo）+ 三个功能函数 + 主循环"，结构清晰、能讲出道理，是 M1 首次 GitHub 提交的理想第一份作品。提交时写一句 README 说明怎么运行，就更像样了（README 明天讲）。
