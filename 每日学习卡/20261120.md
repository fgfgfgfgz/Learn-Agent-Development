## 今日知识点（27 分钟）

### 1. 打开文件：`open()`（10 分钟）

> ### 🔧 函数卡片：`open()`
>
> **① 它是什么**：Python 内置函数，用来"打开一个文件，拿到一个能读写的把手"。像你去图书馆借书——先办借书手续拿到书（文件对象），才能翻页读、拿笔写。
>
> **② 参数**（这里讲最常用的三个）：
>
> | 参数 | 必填/可选 | 默认值 | 说明 |
> | --- | --- | --- | --- |
> | `file`（文件名/路径） | **必填** | 无 | 要打开的文件，如 `"tasks.txt"` |
> | `mode`（模式） | 可选 | `"r"` | `"r"`=读、`"w"`=写（会清空原内容！）、`"a"`=追加（写在末尾） |
> | `encoding`（编码） | 可选 | 系统默认 | **写中文一定写 `encoding="utf-8"`**，否则不同系统上可能乱码 |
>
> **③ 返回值**：返回一个**文件对象**（`TextIOWrapper` 类型）。不是字符串、不是列表——是一个"能读能写的东西"，你要用它的 `.read()` / `.write()` 方法。我实跑确认过：
>
> ```python
> f = open("demo.txt", "w", encoding="utf-8")
> print(f)        # <_io.TextIOWrapper name='demo.txt' mode='w' encoding='utf-8'>
> print(type(f))  # <class '_io.TextIOWrapper'>
> ```
>
> **④ 最小例子**：
>
> ```python
> f = open("hello.txt", "w", encoding="utf-8")  # 打开写入模式
> f.write("你好，文件！")                        # 写进去
> f.close()                                      # 关上（很重要，见坑②）
>
> f = open("hello.txt", "r", encoding="utf-8")  # 打开读取模式
> print(f.read())                                # 你好，文件！
> f.close()
> ```
>
> **⑤ 常见坑**：
> - ① **`"w"` 模式会清空原文件**！一打开就把原来的内容全删了。想保留原内容往后加，用 `"a"`（append）。
> - ② **打开必须关闭**（`f.close()`）。不关的话数据可能没真正写进硬盘，而且文件被"占着"。下面讲的 `with` 就是帮你自动关的。
> - ③ 读不存在的文件会报 `FileNotFoundError`——这就是今天要学的异常处理要解决的。
> - ④ 写中文不指定 `encoding="utf-8"` 可能在别人的电脑上乱码，养成每次都写的习惯。

### 2. 自动关闭：`with` 语句（5 分钟）

每次开文件都惦记着 `close()` 太累，而且中间一旦出错就忘了关。`with` 帮你包办——**离开 with 那段，文件自动关闭**。

```python
with open("hello.txt", "r", encoding="utf-8") as f:
    content = f.read()
    print(content)
# 到这里 f 已经被自动关闭，不用写 f.close()
```

读法：`with open(...) as f:` 意思是"打开文件，把它起名为 f，在这个缩进块里用；用完了自动关"。

我实跑验证过自动关闭确实发生：

```python
with open("demo.txt", "r", encoding="utf-8") as f:
    print(f.read())
print(f.closed)   # True —— with 结束后 f 已关闭
print(f.read())   # ValueError: I/O operation on closed file.
```

注意最后一行：**关了之后再读会报错**（`ValueError`），这正好说明 with 真的帮你关了。以后看到 `ValueError: I/O operation on closed file.` 就知道是"文件关了还在用"。

**从今天起，读写文件一律用 `with` 写法**，不要再用裸 `open()` + `close()`。

### 3. 读写内容：`read()` / `write()`（7 分钟）

> ### 🔧 方法卡片：`f.read()` 与 `f.write()`
>
> **① 它们是什么**：文件对象的两个方法——`read()` 把文件内容读出来，`write()` 往文件里写内容。
>
> **② 参数**：
> - `read()`：可以不给参数（**一次性读全部**）；也可给数字 `read(10)` 表示读前 10 个字符（今天用不到）。
> - `write(内容)`：**必填**，要写进去的字符串。**只能写字符串**，数字要先 `str()` 转。
>
> **③ 返回值**：
> - `read()` 返回**字符串**（`str`），内容是文件的全部文本。空文件返回空字符串 `""`。
> - `write()` 返回**整数**，是"写进去多少个字符"。这个返回值很少用，但你要知道它不是 None。实跑：
>
> ```python
> n = f.write("第一行\n第二行\n")   # 注意 \n 是换行符
> print(n)                          # 8 —— 写了 8 个字符（含两个 \n）
> ```
>
> **④ 最小例子**（逐行读，这是处理清单的标准套路）：
>
> ```python
> with open("tasks.txt", "r", encoding="utf-8") as f:
>     for line in f:              # 文件可以像列表一样一行一行遍历！
>         print(line.strip())     # strip() 去掉行尾的换行符 \n
> ```
>
> **⑤ 常见坑**：
> - ① `read()` 读出来是一整个字符串，里面的换行是 `\n` 字符。想变成"一行一项"的列表，就用上面 `for line in f` 的写法，配合 `line.strip()`。
> - ② `write()` 不会自动帮你换行！要换行必须自己写 `\n`。写清单时 `f.write(t + "\n")`。
> - ③ 文件不存在时 `open(..., "r")` 直接报错，读之前要么先确认文件在，要么用下面的异常处理。

### 4. 出错别崩：`try` / `except`（5 分钟）

程序遇到意外会"崩溃"（抛异常、后面代码全不执行）。`try/except` 让你**提前接住意外**，接住后程序按你写的方案继续走。

```python
try:
    # 可能出错的代码
    with open("tasks.txt", "r", encoding="utf-8") as f:
        return f.read()
except FileNotFoundError:
    # 出错时执行这里
    return ""    # 文件不存在，当作空清单
```

读法：把"可能出错的代码"放进 `try`，如果它抛了 `except` 后面写的那种异常，就跳到 `except` 里执行，程序不会崩。**没出错就只走 try，不进 except。**

今天认两个最常见的异常：

| 异常 | 什么时候发生 | 典型场景 |
| --- | --- | --- |
| `FileNotFoundError` | 打开一个不存在的文件（`"r"` 模式） | 程序第一次运行，tasks.txt 还没创建 |
| `ValueError` | 值不对，比如 `int("abc")` | 把用户输入的非数字转成整数 |

我实跑确认了这两种：

```python
open("不存在的文件.txt", "r")   # → FileNotFoundError
int("abc")                       # → ValueError
```

**用在哪**：`load_tasks()` 里用 `except FileNotFoundError` 处理"第一次运行文件还不存在"——返回空清单，程序正常启动。这样你的待办清单第一次跑、第二十次跑都没问题。

## 动手练习（20 分钟）

产出：`练习/20261120/todo_cli_file.py`

把你 11-19 写的 `todo_cli_func.py` 升级成文件版。下面是**完整可运行版**（我已实跑验证：首次运行空清单不报错、添加后数据能保存到下次运行）。你可以照着敲，也可以拿自己的版本对照修改。

改动其实只有三处，都标了注释：

```python
FILE = "tasks.txt"


def show_tasks(tasks):
    """显示所有任务，带编号"""
    if not tasks:
        print("清单是空的，先添加一项吧")
        return
    i = 1
    for t in tasks:
        print(f"{i}. {t}")
        i = i + 1


def add_task(tasks, new):
    """添加任务"""
    tasks.append(new)
    save_tasks(tasks)              # 改动①：添加后立即写回文件
    return f"已添加「{new}」"


def check_task(tasks, target):
    """检查某项是否在清单里"""
    if target in tasks:
        return f"「{target}」在清单里"
    else:
        return f"「{target}」不在清单里"


def load_tasks():                  # 改动②：新增，启动时从文件读清单
    """启动时从文件读取清单；文件不存在就返回空清单"""
    try:
        with open(FILE, "r", encoding="utf-8") as f:
            tasks = []
            for line in f:
                line = line.strip()
                if line:                 # 跳过空行
                    tasks.append(line)
            return tasks
    except FileNotFoundError:
        return []


def save_tasks(tasks):             # 改动③：新增，把清单写回文件
    """把清单写回文件，每行一项"""
    with open(FILE, "w", encoding="utf-8") as f:
        for t in tasks:
            f.write(t + "\n")


todo = load_tasks()                # 原来这里是写死的 todo = [...] ，改成从文件读

while True:
    print("\n===== 待办清单 =====")
    print("1. 查看清单")
    print("2. 添加任务")
    print("3. 检查某项")
    print("4. 退出")

    choice = input("请选择 1-4：")

    if choice == "1":
        show_tasks(todo)
    elif choice == "2":
        new = input("输入新任务：")
        print(add_task(todo, new))
    elif choice == "3":
        target = input("要检查哪项：")
        print(check_task(todo, target))
    elif choice == "4":
        print("再见！")
        break
    else:
        print("输入有误，请输入 1-4")
```

三个改动看清就够了：① 添加时调 `save_tasks`；② 多了 `load_tasks` 用 try/except 读文件；③ 多了 `save_tasks` 用 with 写文件。其他函数原封不动——这就是当初抽成函数的好处，加功能不用翻遍整个程序。

**跑起来验证三件事**：

1. 第一次运行（还没有 tasks.txt）→ 正常启动、清单为空，不报错——这是 `except FileNotFoundError` 在起作用。
2. 添加两项 → 退出 → **再次运行** → 那两项还在！这就是"持久化"，数据在程序关掉后活了下来。
3. 打开同目录下的 `tasks.txt` 看一眼 → 里面就是一行一项的文本，人也能直接看懂、手动改。

> 求职相关：这份代码现在有"数据 + 4 个函数 + 主循环 + 文件持久化 + 异常处理"，已经是能写进简历的小工具了。面试时被问"你的项目怎么处理数据持久化""第一次运行文件不存在怎么办"，你直接讲这个 `load_tasks` 的 try/except 就行。README 怎么写，下次讲。
